# The officer's entry

What the program does with the officer's answer. The officer proposes and the program checks.

| ID | Requirement | Ver | Status |
|---|---|---|---|
| WB-OFFICER-1 | The program shall start a fresh officer session, one for each issue assigned to the officer's account. Issue: #86. | T | Draft |
| WB-OFFICER-2 | The program shall carry out an answer of the officer only in the fixed form, and shall refuse any other and assign the issue back to the person. Issue: #86. | T | Draft |
| WB-OFFICER-3 | On the answer ready, the program shall assign the issue to the breakdown, or to the tester when the task's file is accepted. Issue: #86. | T | Draft |
| WB-OFFICER-4 | On the answer needs a person, the program shall assign the issue back to the person with the officer's comment. Issue: #86. | T | Draft |
| WB-OFFICER-5 | On the answer a split, the program shall post the pieces as one comment in a fixed form and assign the issue back to the person. Issue: #86. | T | Draft |
| WB-OFFICER-6 | The program shall write the issues of a split only after a yes from a person of enough role, and only from the officer's account. Issue: #86. | T | Draft |
| WB-OFFICER-7 | The program shall never change the text of the person's issue. Issue: #86. | T | Draft |
| WB-OFFICER-8 | The program shall refuse a handover that breaks the rule table, whoever proposed it. Issue: #86. | T | Draft |
| WB-OFFICER-9 | The program shall give the officer's session no role on a piece it has handed out, and no right to merge. Issue: #86. | T | Draft |
